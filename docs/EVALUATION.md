## 6. Re-QA 💰 (PASS 경로까지 확인)

QAting 샘플은 코드를 고치지 않아 FAIL만 볼 수 있습니다. 여기서는 실제로 고친 커밋을 올려 PASS와 FAIL을 함께 봅니다.

1. `npm run reqa:apply` → `git commit -am "Re-QA 시나리오" && git push`
2. 아래 6개 이슈를 담당 팀 프론트엔드로 지정하고 [수정 시작] → [수정 완료로 변경]
3. [디자인 QA] → [Re-QA 실행]

| ID | 코드 변경 | 기대 판정 | 기대 상태 | 결과 |
| --- | --- | --- | --- | --- |
| D01 | `gap-5` → `gap-6` (Tailwind) | PASS | 해결 | |
| D03 | `px-5` → `px-6` (Tailwind) | PASS | 해결 | |
| D07 | `padding: 20px` → `24px` (CSS Modules) | PASS | 해결 | |
| D10 | `gap: 12` → `10` (인라인 style) | PASS | 해결 | |
| D12 | `6px` → `10px` (잘못 고침, styled-components) | FAIL, 다시 읽은 값 `10px` | 재확인 필요 | |
| D13 | 고치지 않음 | FAIL, 다시 읽은 값 `600` | 재확인 필요 | |

| # | 추가 확인 | 기대 결과 | 결과 |
| --- | --- | --- | --- |
| 6-1 | "수정 완료"로 바꾸지 않은 이슈 | 상태 변화 없음 | |
| 6-2 | 이슈 상세 "재검증 기록" | PASS/FAIL과 다시 읽은 코드 값, 새 커밋 | |
| 6-3 | 알림(종 아이콘) | 해결 · 재실패 알림 | |

`results/issues-after-reqa.json`을 저장한 뒤 `npm run score -- --reqa results/issues-after-reqa.json`으로 채점합니다. 끝나면 `npm run reqa:revert`로 되돌릴 수 있습니다.
